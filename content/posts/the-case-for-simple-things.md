# The Case for Simple Things

There is a strange tendency in technology to assume that more is automatically better.

More features. More settings. More integrations. More dashboards. More automation.

Eventually, the thing that was supposed to make life easier becomes something you have to manage.

I think there is another way.

## Simple doesn't mean limited

A simple tool isn't necessarily one that does very little.

It can do exactly what it needs to do, while refusing to take responsibility for things that aren't its job.

A good knife doesn't need a clock.

A notebook doesn't need a social network.

A blog doesn't need a database.

The challenge is deciding where to stop.

> The best feature is sometimes the feature you don't have to build.

## A blog should be boring

At its most basic, a blog has a remarkably simple job:

1. Let someone write something.
2. Turn that writing into a readable page.
3. Let someone else read it.

Everything beyond that is optional.

You don't necessarily need:

- A user account system
- A database
- An administration dashboard
- A recommendation algorithm
- A comment platform
- A proprietary editor
- A complicated publishing workflow

None of these things are inherently bad.

They just aren't necessary for the fundamental job.

## Why Markdown?

Markdown is almost boring enough to be perfect.

A document can be opened in a text editor, read by a human, stored in Git, backed up, copied to another computer or moved to another publishing system.

The format isn't particularly exciting.

That's precisely why it works.
